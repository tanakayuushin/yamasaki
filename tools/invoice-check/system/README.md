# 請求書メール 対応チェック（直近1週間版）— 管理者向けメモ

直近 `Outlook.DaysBack` 日（既定 7 日）の請求書メールを見つけ、社内の対応ルール（コピー・格納・受領返信・フラグ・確認者の分類項目）どおりに
処理されているかをチェックし、結果の画面（HTML）と CSV を出力します。**読み取りのみ**です。

- 必要なもの: Windows ＋ Windows PowerShell 5.1 ＋ デスクトップ版（従来の）Outlook
- 追加インストール不要

## フォルダ構成

```
請求書メールチェック\
  使い方ガイド.html            … 利用者向けの説明（社内の運用に合わせて作成。Git管理外）
  1_はじめに_環境チェック.bat  … このPCで動くかの確認（読み取りのみ）
  2_請求書メールチェック.bat   … チェックの実行。終わると結果の画面がブラウザで開く
  結果\                        … 結果（HTML・CSV）。KeepDays 日より古いものは自動で削除
  system\
    Check-InvoiceMails.ps1     … 本体
    Test-Environment.ps1       … 環境チェック
    config.sample.json         … 設定の見本。コピーして config.json にし、社内の値を入れる
    config.json                … 実際の設定（Git管理外）
    inspect_cache.json         … 添付の確認結果の記録（ハッシュ値と結果のみ。Git管理外）
```

## 判定のしくみ

### 調べる範囲
`Outlook.SearchFolderName` に検索フォルダー（お気に入りにある、受信メールをまとめたもの）の名前を入れると、人が確認しているのと同じ範囲を調べます。
`CopyRootFolder` の中にあるメール（コピー）は除きます。見つからない・空欄の場合は `Outlook.Folders`（既定は受信トレイ）を調べます。
結果の「Outlookフォルダ」列に、メールが実際に入っているフォルダが出ます。

### 請求書メール
件名・本文・添付ファイル名に `Detection.Keywords`（請求書、ご請求 など）があり、次のどれかがあるメール。
- PDF・Excel・Word・PowerPoint・ZIP の添付
- 画像（jpg / png / tif など）の添付（`Detection.MinImageBytes` 未満の小さい画像と、本文に埋め込まれた画像は除く）
- 請求書取得用のリンク（URL に `LinkPatterns` を含む、または近くに `LinkContextKeywords` がある）

### 添付の中身の確認（`Inspection`）
件名・本文・添付ファイル名に言葉がなければ、添付の中身を確認します（1通につき `MaxAttachmentsPerMail` 件、`MaxFileMB` まで）。
| 添付 | 方法 |
|---|---|
| PDF・画像 | Windows 標準の文字認識（OCR）。PDF は先頭から `MaxPdfPages` ページ |
| Excel・Word・PowerPoint（新形式） | 中の文字（マクロは実行しない） |
| ZIP | 中のファイル名（展開しない） |

中身に `Keywords` があるか、`UseRegistrationNumber` が true なら「インボイスの登録番号（T＋13桁）と金額・支払いの記載」があれば請求書とみなします。
一度確認した添付は `system\inspect_cache.json` に「ハッシュ値と結果」だけを記録し、次回は読み直しません（中身の文字は保存しない）。
日本語の文字認識がないPCでは、PDF・画像の中身の確認だけを省きます。

### ルールのチェック
| 項目 | 判定 |
|---|---|
| 対応段階 | 分類項目の確認者の数（元メール＋コピー）→ 0人=未対応 / 1人=1人目済 / 2人以上=完了。`Rules.Staff` が空なら、不備・対象外以外の分類項目をすべて確認者として数える |
| コピー | 元メールと同じ Message-ID のメールが `Outlook.CopyRootFolder` 配下の「○○月分」（`NormalCopyFolderPattern`）にあるか。特定案件は `SpecialProject.CopyFolderPattern` |
| 格納 | `Storage.RootPath\<年>\<月>`（特定案件はその中の `SpecialProject.StorageSubfolderPattern`）に、**請求書のファイル**と中身が同じ（SHA256）ファイルがあるか。請求書のファイル＝ファイル名か中身に `Keywords` がある添付（添付が複数でファイル名で分からなければ中身で見分ける）。分からなければ添付のどれか1つが格納されていれば「済」。リンク型・画像は、取引先名を含むファイルがあれば「済(推定)」 |
| 受領返信 | コピー先（またはコピー元）が返信済みか。`AutoMailSenderPatterns` に当たる差出人は「不要」 |
| コピー先フラグ | 1人目済 → フラグあり、完了 → 完了 |

**請求月＝請求書に書かれた日付の月**です。請求書のファイルを文字認識（Excel は中の文字）して、`InvoiceDate.Labels`（請求日・発行日など）のすぐ後の日付、なければ最初の日付を使います。`InvoiceDate.ExcludeLabels`（支払期限・納期など）の後ろの日付は使いません。読み取れない場合は、コピー先フォルダ名の月 → 件名の「○月分」 → 受信月と前月で推測します。

格納の確かめ方（請求書のファイルごと）
1. **格納場所の全部**（`Storage.RootPath` の下のすべてのファイル）から、中身が完全に同じ（SHA256）ファイルを探す
2. なければ **内容で照合**（`Storage.ContentMatch`）：文字認識で「登録番号（T＋13桁）・請求金額・請求書の日付」を読み、
   「金額が一致し、登録番号か日付も一致」または「登録番号と日付が一致」するPDFを探す。
   相手は、請求月と前後 `MonthRange` か月のフォルダのPDF＋ファイル名に取引先名が入ったPDF（最大 `MaxCandidates` 件）。
   格納場所のPDFの読み取り結果は、ファイルの場所・大きさ・更新日時ごとに `inspect_cache.json` に記録し、次回は読み直さない
3. 見つかった場所が請求月のフォルダなら「済」（2 なら「済(内容一致)」）、別の月なら「要確認」。請求月を推測した場合は、別の月でも「済」
4. 見つからなければ、請求月のフォルダに同じ名前のファイルがあれば「要確認」、画像・Excel は取引先名を含むファイルがあれば「済(推定)」、それ以外は「未」

| 届き方 | 判定 |
|---|---|
| ファイル名か中身で請求書と分かった添付がある | そのファイルがすべて格納されていれば済 |
| 分からず、取得用のリンクがある | 添付（PDF）のどれかが格納されていれば済。なければ取引先名を含むファイルで「済(推定)」 |
| 分からず、リンクもない | 添付（PDF、なければ全部）のどれか1つが格納されていれば済 |

結果の画面の「保管が未のもの」ボタンで、確認の段階に関係なく、格納が「済」「不備」以外のメールだけを表示できます。

### 注意（要注意）
- 件名・本文に `Caution.BankChangeKeywords`（振込先変更、口座変更 など）がある
- `Caution.DangerExtensions`（exe・html・マクロ付き Office など）の添付がある

### 結果
| 結果 | 条件 |
|---|---|
| 要注意 | 注意に当たるものがある |
| 漏れあり | 確認者がいるのに、コピー・格納・返信・フラグのどれかが足りない |
| エラー | そのメールの確認中にエラー（他のメールの確認は続ける） |
| 対応待ち | 未対応、または1人目の対応は揃っていて2人目待ち |
| OK | 2人の確認が済み、すべて揃っている |
| 対象外 | `Rules.ExcludeCategories` の分類項目が付いている |

## 安全面
- メール・フラグ・分類項目・ファイルは変更しない。添付は一時フォルダに取り出して照合し、終了時に削除
- 結果の画面にメールの文字を入れるときは無害化（HTML エスケープ）し、外部の読み込みも禁止（CSP）
- 結果にURLは載せず、リンク先のドメインだけをクリックできない表記（`example[.]com`）で表示
- Outlook が閉じて接続が切れた場合は、そこまでの結果を保存して終了
